# React组件开发规范

## 一、基本要求
### 1. 组件名称
- 组件名称必须以 `.tsx` 结尾，且以 `PascalCase` 命名

### 2. 目录结构
- 组件的父目录名称为 `components`
- 组件的入口文件名称为 `index.tsx`
- 组件的案例文件名称为 `demo.tsx`
- 组件的入参类型文件名称为 `types.ts`
- 组件的文档文件名称为 `README.md`

## 二、开发规范
- ==遵循React开发规范==：必须遵循React开发规范
- ==明确入参类型==：必须提供入参的typescript类型定义
- ==需要提供demo==：必须提供案例文件，用于展示组件的使用方式
- ==需要提供文档==：必须提供文档，用于展示组件的使用方式

## 三、Agent规范

整理开发流程按如下顺序：
* 需求分析
* 方案设计
* 代码编写
* Demo编写

### 1. 需求分析
- ==组件代码根目录确认=：需要用户确认组件代码根目录，若用户未提供则需要询问用户，如果是页面组件，放在src/pages/{pageName}/components下，如果是组件库组件，放在src/components下
- ==需求确认==：需要用户确认，若用户未提供则需要询问用户，确认后进行下一步方案设计

### 2. 方案设计
- ==组件设计方案文档==：需要计方案文档，用于展示组件的设计思路和设计细节，文档输出在`README.md`
- ==组件的入参类型定义==：需要提供入参的typescript类型定义，用于校验入参类型，并提示用户入参类型错误
- ==方案确认==：设计方案需要用户确认，然后进行下一步代码编写

### 3. 代码编写
- ==组件代码==：需要编写组件代码，按照目录规范编写代码

### 4. Demo编写
- ==组件案例==：需要编写组件案例，用于展示组件的使用方式
