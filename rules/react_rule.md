# React Best Practices

## 组件结构
- 优先使用函数组件而非类组件
- 保持组件尽可能简洁，且专注于单一功能
- 将可复用逻辑提取到自定义 Hook 中
- 使用组合优于继承
- 使用 TypeScript 实现合适的 props 类型
- 将大型组件拆分为更小且聚焦的组件

## Hooks
- 遵循 Hooks 的使用规则
- 用自定义 Hooks 封装可复用逻辑
- 保持 Hooks 功能单一且简明
- 在 useEffect 中合理设置依赖数组
- 在需要时在 useEffect 中实现清理操作
- 避免嵌套使用 Hook

## 状态管理
- 对于局部组件状态使用 useState
- 对于复杂状态逻辑使用 useReducer
- 共享状态时使用 Context API
- 状态应尽量靠近其使用的地方维护
- 使用合理的状态管理避免 props 层层传递
- 仅在必要时使用状态管理库

## 性能
- 正确使用记忆化优化（useMemo、useCallback）
- 对性能开销大的组件使用 React.memo
- 避免不必要的重新渲染
- 实现合适的懒加载
- 在列表中使用合适的 key 属性
- 分析并优化渲染性能

## 表单
- 使用受控组件管理表单输入
- 实现有效的表单校验
- 正确处理表单提交状态
- 合理展示加载和错误状态
- 对复杂表单可使用表单库
- 实现表单的无障碍访问（可访问性）

## 错误处理
- 实现错误边界（Error Boundaries）
- 正确处理异步错误
- 向用户展示友好的错误信息
- 实现合理的兜底（fallback）UI
- 适当记录错误日志
- 优雅处理边界&极端情况

## 测试
- 为组件编写单元测试
- 为复杂流程实现集成测试
- 使用 React Testing Library
- 测试用户交互
- 覆盖错误分支的测试
- 使用合适的 mock 数据

## 可访问性
- 使用语义化 HTML 元素
- 正确使用 ARIA 属性
- 确保键盘可导航
- 用屏幕阅读器测试效果
- 处理好焦点管理
- 为图片提供合适的 alt 文本

## 代码组织
- 将相关组件分组整理
- 使用合适的文件命名规范
- 实现规范的文件目录结构
- 把样式靠近组件组织
- 合理使用导入/导出语法
- 对复杂组件逻辑进行文档说明
